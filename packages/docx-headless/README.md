# Headless Word exchange (proposal)

This Node-only package imports/exports bounded DOCX bytes through a neutral typed document model. It does not construct a browser editor, download files, fetch document resources, persist data or decide review records.

`importDocx(bytes)` returns the document, section ranges/layout/stories, named styles, embedded image data and explicit conversion losses. `exportDocx(document, mode, assets, stories, styleDefinitions)` returns a Buffer. `exportDocxSections(input, mode)` preserves independent section stories, page geometry and equal-width columns while rebasing package identities. Modes are `retain-review`, `original` and `final`; projections do not mutate their input.

Native review supports run insertion/deletion/formatting, paragraph insertion/deletion/formatting/split/join and classic body comments. Source author attribution is retained separately as `importedAuthor`; it is not an authenticated application identity. Applications preserve originals, canonical document identity and resolved/history records themselves. Word ignores header/footer comment anchors; exporting them is rejected rather than emitting invalid review.

Nested rectangular tables retain ordered cell blocks, direct table/cell borders, solid RGB shading, complete margins, table width/alignment/layout, row keep-together and repeated-header settings. A cell has exactly one content authority: legacy `paragraphs`, or `blocks` with an empty `paragraphs` array. Nested identities, comments and paragraph review are validated recursively; cells cannot share paragraph-boundary revisions. Models reject cycles and tables deeper than eight levels.

Paragraph exchange retains direct borders/shading, keep-lines/widow settings, right indents and exact/minimum line heights. Section exchange retains header/footer distances and explicit continuous/next-page breaks. Section breaks attach to an existing final paragraph where possible rather than inserting an extra blank paragraph. The independent OOXML fixture exercises these properties together with an image, comments and a pending insertion.

CRC, byte/entry/expansion bounds, streaming XML complexity limits, relationship validation and source-loss diagnostics run before conversion. Only HTTP(S) external hyperlink relationships are accepted; resources are never fetched. Images must be supplied as verified bytes. Merged cells, floating content, partial margin inheritance, unsupported decoration, conditional stories, embedded-font approval and authored PAGE-field placement still require explicit conversion handling. Exact Microsoft Word compatibility and a complete print-fidelity corpus are not certified by these unit tests.

Development probing is `node dist/test/probe-corpus.js source.docx separate-candidate.docx`. It uses exclusive candidate creation, reports losses and exact paragraph text comparison, and never declares print acceptance. Two retained illustrated modules preserve their imported paragraph text sequence after export/reimport. Independent LibreOffice inspection of one candidate nevertheless changes 30 source pages into 11 candidate pages with body text absent from rendered output. This is a failed fidelity candidate; the missing font/style/story support remains a release blocker.

Run `pnpm --filter @hufe921/canvas-editor-plugin-docx-headless test`. Provenance and licenses are retained in `PROVENANCE.md` and `LICENSE`. This is an upstream proposal, not a separately maintained application fork.
